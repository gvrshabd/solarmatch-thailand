SolarMatch security review — 2026-11-05

Scope: source inspection of lib/server authentication, preview/staging access,
assessment token, admin request/CSRF boundaries; app/admin/api routes; installer
authentication/configuration, portal company ownership, share links, rate limits,
phone proof, payment and LINE provider/webhook processing, and privacy redaction.
Inspected public lead submission gates and local-only test endpoints. Dependency
audit evidence is dependency-audit-before.json (full dependency graph, before
central dependency remediation). No credentials or real customer data were read.

Verified fixes:
1. Medium — administrative uploads parsed the entire multipart body before
   enforcing individual file size limits. Extra fields, multiple files, or a large
   file could consume memory before rejection. Both media and contract routes now
   cap actual streamed envelope bytes before multipart parsing: 5,000,000 bytes
   plus 64 KiB for media; 10 MiB plus 64 KiB for contracts. Declared lengths are an
   early rejection only; absent/false lengths cannot bypass actual-byte counting.
   Oversized requests return 413. Cancellation is not awaited indefinitely.
2. Medium application exposure / high dependency advisory — image upload trusted
   a caller-controlled JPEG/PNG/WebP MIME label before dispatching arbitrary
   content into image-size. Version 2.0.2 has high infinite-loop advisories in
   ICNS/JXL/HEIF parsers (GHSA-w3rx-r6r6-pgpr, GHSA-5p2g-fcmc-qvqq). Actual raster
   magic must now match the declared permitted format before any dimension parser
   invocation. Unsupported and mismatched bytes return 400 before storage. This
   also prevents relabeled SVG from entering the raster media pipeline. Package
   upgrades are handled centrally and should retain this independent boundary.

Tests: tests/unit/admin-upload-boundaries.test.ts exercises route rejection before
parser/storage, declared and actual-stream envelope limits, a stalled cancellation,
normal multipart parsing, extra-field overflow, and relabeled SVG/ICNS/JXL. Focused
existing suites cover administrator sessions/CSRF, installer auth, tenant/share
isolation, privacy, provider signatures/payment matching, phone proof, rate limits.
Final test results and dependency audit after remediation are in the parent review.

Observed controls: administrative mutations use authenticated identity and CSRF;
installer mutations require exact origin and bounded JSON; account actions scope
company ownership; staff shares are hashed high-entropy expiring/revocable bearer
tokens with limited projection; contact disclosure uses suppression/withdrawal
conditions; OTP attempts are charged atomically and proofs bound to phone/session;
provider webhook signatures and provider-side payment/order/amount matching are
checked; production platform mode/origin and local-only boundaries fail closed.
No concrete bypass of those controls was verified in this review.

Limits: source and local tests, not an external penetration test or proof of all
possible races. Deployed Cloudflare Access, bucket policies, secrets, account
configuration, real provider behavior and real-data retention were not inspected.
PDF magic validation is not malware scanning. The new envelope cap does not impose
a network read deadline. Other authenticated admin JSON endpoints still rely on
runtime request limits rather than a shared explicit application byte cap.
Audit advisory severity describes dependency reachability risk, not proof that
every advisory is exploitable through this vinext deployment. No remote changes,
deployment, business-operation enabling, messages, or data writes were performed.
