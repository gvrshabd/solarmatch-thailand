SolarMatch Pulse landing: Safari motion repair, 2026-11-03

Application commit: 14508d1 (parent 4d9ce6d).
Scope: installer landing animation, its generated assets, and regression checks.
No migration, API, portal, calculator, operational flag or consent change.

Established causes
1. Four large animated CSS blur layers plus SVG turbulence were expensive in
   high-density Windows headless WebKit. The original prototype also exhibits
   this behavior. Original circle colours, blur extents and grain were rendered
   into trusted local PNGs; animation geometry and timing remain unchanged.
2. The feed discarded elapsed time beyond 50ms per frame. Delayed rendering
   therefore also slowed the intended scrolling rate. It now uses actual visible
   elapsed time, with background-tab and user-interaction time excluded.
3. In mobile WebKit emulation, resizing the page changed innerWidth but left the
   layout viewport/media query at its previous width. Reproduced independently
   on blank HTML. The test explicitly updates the emulated viewport meta width
   after resizing; it still checks both axes, manual scrolling and touch resume.
   No application viewport workaround was added.

Limits
Windows headless WebKit still has lower frame throughput at high density: the
3x/1180px stress sample recorded four callbacks in 1.5 seconds versus one in the
prototype. Correct scrolling speed is not proof of 60fps. No physical iPhone,
iPad or macOS Safari acceptance is claimed. Actual-device visual smoothness
remains a device verification item, not an omitted automated failure.
